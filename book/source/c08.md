## De la fórmula a un contrato computacional

La función que recibe el integrador debe devolver derivadas, no el estado futuro. Si escribes `return [alfa-delta*x]`, has traducido una tasa. Si escribes `return [x+alfa-delta*x]`, has añadido una variable con unidades de concentración a términos con unidades de concentración/tiempo. El programa puede ejecutarse sin error y, aun así, dejar de representar la ecuación. El contrato de `solve_ivp` especifica la forma de entrada y salida; el balance físico viene del modelo [R05] [A01].

Usa un orden estable para estados y parámetros. Separa la función del modelo, el diseño de la entrada, las condiciones iniciales, la llamada al integrador y el gráfico. Esa separación permite cambiar tolerancias sin modificar la biología y contrastar dos hipótesis con el mismo procedimiento numérico. NumPy y SciPy son herramientas académicas de cálculo; sus artículos y documentación describen funciones y alcance [A21] [A22] [R03] [R05].

```python
from dataclasses import dataclass
import numpy as np
from scipy.integrate import solve_ivp

@dataclass(frozen=True)
class Parametros:
    alfa: float = 12.0       # nM/h
    delta: float = 0.3       # 1/h

def rhs(t, estado, p):
    x, = estado
    return [p.alfa - p.delta*x]

p = Parametros()
t_salida = np.linspace(0.0, 20.0, 201)
sol = solve_ivp(lambda t, y: rhs(t, y, p),
                (0.0, 20.0), [5.0], t_eval=t_salida,
                rtol=1e-8, atol=[1e-10])
if not sol.success:
    raise RuntimeError(sol.message)
exacta = p.alfa/p.delta + (5-p.alfa/p.delta)*np.exp(-p.delta*sol.t)
print(np.max(np.abs(sol.y[0]-exacta)))
```

El ejemplo es original y comprueba un problema con solución analítica conocida. `frozen=True` evita modificar accidentalmente el objeto de parámetros; no añade una propiedad científica al modelo. `sol.success` informa del éxito del procedimiento numérico, no de la validez biológica. La comparación con la solución exacta comprueba la implementación dentro del problema elegido [R05] [R09] [A01].

## Qué hacen realmente Euler y Runge–Kutta

Euler sustituye el cambio durante un paso por la pendiente al comienzo: xₖ₊₁=xₖ+h·f(tₖ,xₖ). La expansión de Taylor de la solución exacta incluye además h²x''/2 y términos superiores. Al omitirlos, el error de un paso es de orden h² bajo regularidad suficiente; tras muchos pasos, el error global típico es de orden h en un intervalo fijo. Ambas afirmaciones tienen hipótesis de suavidad y estabilidad [A01], §2.1.4; [A02].

Para x' = −δx, Euler produce xₖ₊₁=(1−δh)xₖ. La solución exacta es positiva para x₀ positivo. Euler conserva positividad solamente si δh≤1; su estabilidad lineal exige |1−δh|<1, o 0<δh<2. Hay un intervalo donde el algoritmo es estable pero alterna de signo. Una concentración negativa en ese intervalo es un fallo de representación física, aunque la secuencia tienda a cero [A01] [A02].

Los métodos Runge–Kutta combinan varias evaluaciones de pendientes dentro del paso. RK45 emplea una pareja de órdenes para estimar error y adaptar h. No es el RK4 clásico con un paso fijo, aunque ambos pertenezcan a la misma familia. La malla solicitada con `t_eval` se refiere a la salida; el algoritmo selecciona pasos internos y puede interpolar la solución entre ellos [R05] [R06].

## Interpretar tolerancias por variable

Una prueba de error local utiliza escalas del tipo atolᵢ+rtol·|xᵢ|. `rtol` es relativa y `atol` tiene la unidad del estado correspondiente. Si una especie ronda 10⁴ nM y otra 10⁻⁵ nM, una única tolerancia absoluta puede tratar la segunda como numéricamente irrelevante. Un vector `atol` permite definir escalas distintas; su elección debe relacionarse con la precisión necesaria para el observable [R05].

No confundas tolerancia local con cota garantizada del error global. Un resultado que cambia al pasar de rtol=10⁻⁶ a 10⁻⁹ merece atención, pero la diferencia entre ambas soluciones tampoco demuestra que la segunda sea exacta. Combina refinamiento, comparación entre métodos cuando proceda y pruebas específicas: conservación, solución analítica, simetría o un límite conocido [A01] [R05].

Para un oscilador, una pequeña discrepancia de período se acumula como diferencia de fase. Comparar el valor de la proteína en t=10⁴ puede exagerar una discrepancia temporal pequeña. Comprueba período, amplitud, distribución de intervalos entre máximos y fase después de alinear ciclos cuando ese sea el objetivo. No alinees curvas si lo que se pretende evaluar es precisamente el error de fase [A01], §§4.3 y 7.4.

## Rigidez: dos escalas que exigen métodos diferentes

Imagina dos modos de decaimiento con tasas 1 y 1000 h⁻¹. El segundo desaparece rápidamente, pero un método explícito puede seguir necesitando pasos pequeños para mantener estabilidad aunque solo te interese el modo lento. Esa restricción motivada por estabilidad, más que por precisión de la salida observada, caracteriza muchos problemas rígidos. La separación de escalas ayuda a reconocerlos, pero no todo modelo multiescala es igual de difícil en cada intervalo [A01], §2.2; [R07] [R08].

Radau es un método implícito de Runge–Kutta y BDF pertenece a la familia de fórmulas de diferenciación hacia atrás. Pueden manejar regímenes rígidos con más eficacia, a costa de resolver problemas algebraicos internos. Facilitar el Jacobiano y, en redes grandes, su estructura dispersa puede reducir el trabajo. El artículo de SciPy y las páginas de cada integrador permiten comprobar las opciones actuales [A22] [R05] [R07] [R08].

El Jacobiano Jᵢⱼ=∂fᵢ/∂xⱼ también sirve para análisis dinámico, pero en un solver cumple una función numérica. No cambies el modelo para obtener un Jacobiano más cómodo. Comprueba el Jacobiano analítico comparando Jv con [f(x+εv)−f(x−εv)]/(2ε) en puntos válidos. Esa prueba direccional detecta errores de orden y de derivación sin tener que imprimir toda la matriz [A01], §4.2; [R05].

## Eventos y discontinuidades

Un evento e(t,x)=0 detecta una condición como alcanzar un umbral. El integrador busca cambios de signo durante los pasos; puede perder varios cruces dentro de un paso grande. Si la velocidad de los eventos importa, limita el paso máximo y compara resultados al refinarlo. `direction` restringe el sentido del cruce y `terminal` permite detener la integración [R05].

Una discontinuidad conocida en la entrada se maneja de forma clara dividiendo el intervalo. Integra hasta T, conserva el estado final, cambia la definición de la entrada y reinicia. Un salto de estado, como un reparto idealizado en división celular, requiere además aplicar una regla x⁺=R(x⁻). Una entrada escalón y un salto de estado son operaciones matemáticas distintas [A01], §§2.1 y 3.4; [R05].

### Variables: poner nombre a una cantidad

En Python el signo igual asigna un valor a un nombre. «x = 2» guarda un valor; «x == 2» pregunta si dos valores son iguales. Los decimales se escriben con punto, aunque el libro use coma en el texto. La multiplicación necesita asterisco y la potencia se escribe con dos asteriscos.

Una lista agrupa elementos. Sus posiciones empiezan en cero. Una función agrupa instrucciones y devuelve un resultado con return. La indentación forma parte del lenguaje [R09]:

~~~python
tiempos = [0.0, 1.0, 2.0]
valor_inicial = 8.0

def aproximacion_lineal(x, perdida, paso):
    cambio = -perdida * x
    return x + paso * cambio

nuevo = aproximacion_lineal(valor_inicial, 0.5, 0.1)
print(tiempos[0], nuevo)
~~~

El resultado es 0.0 y 7.6. Primero calculaste una velocidad de pérdida de −4 unidades por tiempo. Durante un paso de 0,1, aproximaste una pérdida de 0,4. El nombre «cambio» en la función representa una velocidad, no una cantidad perdida; escribir unidades en comentarios evita confundirlas.

## Aplicación complementaria: Resolver sin engañarte: pasos, tolerancias, rigidez y eventos

### Una derivada no contiene todavía una trayectoria

La ecuación te dice cómo cambia el estado en cada instante. Un integrador numérico combina muchas aproximaciones para avanzar. El resultado tiene error de cálculo, incluso cuando la ecuación y los parámetros son exactos.

Considera un modelo original de pérdida, con x(0) = 1 y δ positivo:

$$
\frac{dx}{dt}=-\delta x
$$

La solución exacta es x(t) = exp(−δt). Será nuestra referencia para evaluar métodos. No usamos datos experimentales.

Euler toma la pendiente actual y la mantiene durante un paso h:

$$
x_{j+1}=x_j+h(-\delta x_j)=(1-\delta h)x_j
$$

Conoces así el siguiente estado a partir del actual. La aproximación mejora al reducir h, pero no cualquier paso produce una trayectoria físicamente razonable.

*Fuentes de este apartado y del caso: [A01], [R05], [R06], [R07], [R08].*

### Estabilidad y positividad son condiciones distintas

La solución exacta decae. Para que Euler también reduzca el tamaño de una perturbación debes pedir:

$$
|1-\delta h|<1
$$

Para h y δ positivos, esto equivale a 0 < δh < 2. Sin embargo, si δh está entre uno y dos, el factor es negativo: el valor alterna de signo mientras su amplitud disminuye. Es estable en este sentido, pero produce concentraciones negativas.

Para conservar valores no negativos en este ejemplo necesitas además δh ≤ 1. Con δ = 2 y h = 0,75, el factor es −0,5: alterna y decae. Con h = 1,1, es −1,2: alterna y crece. Ninguno reproduce la pérdida física positiva.

Estas condiciones se derivan para esta ecuación lineal. Una red no lineal exige analizar sus escalas y estructura; no apliques automáticamente el mismo número a cualquier modelo.

*Fuentes de este apartado y del caso: [A01], [R05], [R06], [R07], [R08].*

### Error local frente a error global

Imagina comenzar un paso desde el valor exacto. El error introducido en ese único paso es el error local. En Euler, para una solución suficientemente suave, es de orden h². Después de muchos pasos, los errores se propagan y acumulan; en un intervalo fijo el error global suele ser de orden h.

Eso sugiere un ejercicio: divide h por dos y comprueba si el error final se reduce aproximadamente a la mitad. No se exige que la proporción sea exactamente dos para un paso grande.

~~~python
from math import exp
from scipy.integrate import solve_ivp

def euler(h, final=2.0):
    pasos = round(final / h)
    if abs(pasos * h - final) > 1e-12:
        raise ValueError("El paso debe dividir el intervalo")
    x = 1.0
    for _ in range(pasos):
        x = x + h * (-2.0 * x)
    return x

exacto = exp(-4.0)
for h in (0.25, 0.1, 0.05):
    calculado = euler(h)
    print(h, calculado, abs(calculado - exacto))

def cambio(t, estado):
    return [-2.0 * estado[0]]

for metodo in ("RK45", "Radau", "BDF"):
    sol = solve_ivp(
        cambio, (0.0, 2.0), [1.0],
        method=metodo, rtol=1e-7, atol=1e-10
    )
    if not sol.success:
        raise RuntimeError(sol.message)
    print(metodo, sol.y[0, -1], sol.nfev)
~~~

La referencia es aproximadamente 0,0183156. Con pasos 0,1 y 0,05, Euler produce errores aproximados de 0,00679 y 0,00353. La razón está cerca de dos. Ese acuerdo comprueba la implementación y el régimen esperado.

*Fuentes de este apartado y del caso: [A01], [R05], [R06], [R07], [R08].*

### RK45, Radau y BDF responden a necesidades diferentes

RK45 en SciPy usa un par de fórmulas Runge–Kutta de órdenes cinco y cuatro para estimar error y adaptar pasos [R06]. Es un punto de partida razonable para sistemas sin rigidez, pero no transforma automáticamente un modelo mal condicionado en uno sencillo.

Radau es un método implícito de orden cinco, apropiado para problemas rígidos [R07]. BDF utiliza fórmulas implícitas de diferenciación hacia atrás con orden variable [R08]. Los métodos implícitos resuelven problemas adicionales en cada paso; un paso no cuesta lo mismo en todos los métodos. «nfev» cuenta evaluaciones de la función, no todo el trabajo computacional.

La rigidez puede aparecer cuando procesos rápidos estables obligan a un método explícito a usar pasos muy pequeños durante una dinámica global lenta. Por ejemplo, una tasa de pérdida de 1000 por hora limita Euler a pasos menores de 0,002 horas para estabilidad, aunque quieras estudiar 100 horas. Un integrador implícito puede manejar mejor esa diferencia de escalas.

*Fuentes de este apartado y del caso: [A01], [R05], [R06], [R07], [R08].*

### Tolerancias que puedas interpretar

Las tolerancias relativas y absolutas establecen la escala usada para controlar estimaciones de error local [R06]:

$$
s_i=\mathrm{atol}_i+\mathrm{rtol}|x_i|
$$

No constituyen una garantía de error global ni un intervalo de confianza biológico. Si una variable ronda cien y otra una millonésima, una única tolerancia absoluta puede ser inadecuada. Ajusta escalas o usa tolerancias absolutas por componente.

Compara dos tolerancias razonables y comprueba que la cantidad científica de interés cambia poco. No sigas reduciendo tolerancias para obtener cifras irrelevantes respecto a la incertidumbre de datos y parámetros. Un valor negativo pequeño requiere diagnóstico; recortarlo a cero sin analizarlo puede romper balances.

*Fuentes de este apartado y del caso: [A01], [R05], [R06], [R07], [R08].*

### Eventos y tiempos de salida

«t_eval» pide resultados en determinados tiempos; no fija todos los pasos internos. Un evento busca un cruce por cero de una función [R05]. Aquí detectamos cuándo x baja de 0,2:

~~~python
from scipy.integrate import solve_ivp

def cambio(t, estado):
    return [-2.0 * estado[0]]

def umbral(t, estado):
    return estado[0] - 0.2

umbral.direction = -1
umbral.terminal = True

sol = solve_ivp(
    cambio, (0.0, 5.0), [1.0],
    events=umbral, rtol=1e-8, atol=1e-10
)
if not sol.success:
    raise RuntimeError(sol.message)
print(sol.t_events[0][0])
~~~

La respuesta es aproximadamente 0,804719 horas, porque el tiempo exacto es ln(5)/2. Un evento puede pasar inadvertido si hay varios cruces dentro de un paso. Si conoces un cambio discontinuo de entrada, integra por tramos y reinicia desde el estado alcanzado. Pedir una gráfica más densa no arregla por sí solo una discontinuidad mal representada.

*Fuentes de este apartado y del caso: [A01], [R05], [R06], [R07], [R08].*
